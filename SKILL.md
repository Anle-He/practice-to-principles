# Practice to Principles

Turn applied knowledge into reusable principles without confusing source claims with validated experience.

## Protocol

1. Before substantial application, read `references/active.md` and use only principles relevant to the current scope.
2. Treat one completed decision, action, or review as one application episode. Run at most one distillation pass per episode.
3. Stop without writing when the episode only retrieved information, produced no new learning, or lacks meaningful evidence.
4. Search active and candidate principles first. Update an overlapping entry instead of creating a duplicate.
5. Record novel learning in `references/candidates.md` using its schema. Preserve source, scope, evidence, exceptions, and counterevidence.
6. Never increase confidence merely because a source is persuasive. Merge practical support and contradiction explicitly.
7. Promote a candidate to `references/active.md` only after repeated practical support and Anle's explicit confirmation.
8. Move disproved or superseded principles to `references/retired.md`; never erase their history.
9. Briefly report any recorded, promoted, revised, or retired principle.

## Boundaries

- Modify only this skill's reference files unless Anle explicitly authorizes another target.
- Never rewrite system instructions, project rules, `AGENTS.md`, `ANLE.md`, or external memory automatically.
- Keep every principle narrow enough to state when it applies and when it does not.
